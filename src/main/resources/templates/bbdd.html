8. pg_dump y registro

No se ha exportado la base de datos
  • aviso

El propio servidor de PostgreSQL genera el respaldo con COPY (SELECT 1) TO PROGRAM 'pg_dump … -F c': formato custom (binario y comprimido) con las tablas, los datos, las secuencias, las restricciones y los índices, que se restaura con pg_restore. Después la base de datos se registra como BBDD objetivo en el repositorio de la aplicación, para poder analizar consultas sobre ella.

9. Restaurar en otro servidor (opcional)

No se ha restaurado la base de datos
  • aviso

Lleva la base de datos al PostgreSQL de otro equipo de la red: la API restaura allí el respaldo del paso 8 (tienda_demo.dump) con pg_restore --create y ejecuta ANALYZE, porque el respaldo no lleva las estadísticas. En ese equipo, PostgreSQL debe aceptar conexiones de la red (listen_addresses, pg_hba.conf y firewall), el usuario necesita permiso para crear bases de datos (CREATEDB) y la versión debe ser igual o mayor que la de la aplicación. La base de datos no debe existir allí.
